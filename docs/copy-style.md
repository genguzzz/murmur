# Murmur 文案规范

Murmur 是一个私人日记与待办工具，用户把真实的生活、情绪、工作交给它。文案要严谨、靠谱、尊重用户，像一个成熟的正式产品（参考 Apple 中文界面、印象笔记、滴答清单的语气）。

## 原则
1. 准确：说清楚发生了什么、结果是什么、下一步能做什么。状态用“正在…”“已…”“未能…”。
2. 克制：不卖萌、不撒娇、不套近乎。禁用语气词和口头禅：啦、呀、哦、哈、嘛、～、搞定、随便说、乱也没关系、轻松一下、去看看吧、好了告诉我、先放着、带你去。不用感叹号、不用表情符号。
3. 尊重：称呼用户为“你”。不替用户下判断（不说“你肯定…”“别担心”），不评价用户（不说“你很棒”）。出错时不责怪用户，说明原因和解决办法。
4. 中性的产品口吻：界面标签、按钮、提示、空状态都用中性陈述，不用拟人化的第一人称（不写“我在听”“让我看看”“我会帮你…”）。需要指代产品时用“Murmur”。只有 AI 在对话里回答问题时才用“我”。
5. 按钮：动词或动词 + 对象，2–6 字，如“保存记录”“撤销”“查看记录”“删除”“重试”“稍后处理”。
6. 简洁但完整：一句话说完一件事，不堆修饰语。数字、时间写准确（“3 条记录”“明天 09:00”）。中文与数字、英文之间留空格。
7. 隐私说明要具体可信，例如“录音只保存在这台设备上”，不夸大、不承诺做不到的事。

## 示例（改前 → 改后）
- 先回去，好了告诉我 → 返回，完成后通知我
- 没听出要做什么，先放着 → 未能判断这段内容的用途，已放入待确认
- 整理好了，带你去看看 → 已整理完成
- 记下了 → 已保存为记录
- 后续整理好了 → 后续记录已整理完成
- 完成了 → 已完成
- 定好了 → 已设置提醒时间
- 删掉了 → 已删除
- 都处理完了 → 没有待确认的录音
- 我在听 / 想聊点什么？ → 正在录音 / 今天想记录什么？
- 多记几条，规律才会出现 → 记录达到 2 条后可以分析规律
- 出了点问题：xxx → 处理失败：xxx
- 没有待办，轻松一下 → 没有待办事项
- 收到了，正在转写这段话… → 正在转写录音…
